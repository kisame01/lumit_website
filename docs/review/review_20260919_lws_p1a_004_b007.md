## 4. Five mutations the contract did not ask for

**R5 — the collapse is correctly guarded.** Change `about/`'s footer one way and `contact/`'s another,
so the five non-reference pages no longer agree. The gate does **not** collapse: it names both
differing pages and leaves `index.html` alone. The rule fires only when the others are unanimous,
which is what §2.2 required and the case where the reference really is the odd one out.

**R7 — no false positive on lookalike tags.** Adding `<headerish></headerish>` and a `div` carrying
the attribute `data-x="<header"` to a page leaves the gate green. The `(?=[\s>/])` lookahead does its
job, including inside an attribute value, which the contract did not ask for.

**R9 — the balance check is broader than specified, and that is a bonus.** `BALANCE_TAGS` is derived
from the `CHROME` start tags plus `script`, so it covers `section` wherever it appears. An unbalanced
`<section>` anywhere in a page — not only in the closing block — reports:
`how-we-work/index.html:121  B-007 <section> has 6 start and 5 end tags`. Real coverage the contract
did not think to ask for.

**R8 — the disclosed false positive is real, and correctly disclosed.** A commented-out
`<!-- <script> old thing -->` fires `B-007 <script> has 2 start and 1 end tags`. The implementer
declared this in its §6. It is the right trade: a gate that occasionally complains about a commented
tag is better than one that misses a broken one, and this repository has no commented-out markup.
**Left as a known behaviour, not a bug.** Anyone commenting out a tag here should delete it instead.

## 5. The implementer's push-back on M5 — it is right, and the contract is wrong

**The contract contradicted itself and the implementer found the seam rather than papering over it.**

§2.2 says: if every non-reference page's block is identical and differs from `index.html`'s, emit one
violation naming `index.html`. §2.4 says the LWS-P1A-002 suppression stays exactly as it is — a block
failing its count check suppresses B-004 for that block on that page. On M5, `index.html`'s footer
count is 0, so **§2.2 says collapse and report, §2.4 says suppress.** They cannot both hold.

The implementer followed §2.2 literally, reported the conflict quoting the lines, and did not adjust
either rule to make the prediction come true. That is §5 and RULE 002 obeyed under exactly the
pressure they exist for. **Fifth contract in a row where the push-back was worth reading.**

**Adjudication: §2.4 wins.** B-005 already reports "index.html has no footer" precisely and
completely. The extra B-004 line is a second report of one defect, which is the thing B-007b was
written to stop. Reporting a page's missing block as "differs from the other 5" is also the less
informative of the two lines.

**The reviewer wrote and tested the fix before recommending it.** One line, placed at the top of the
`CHROME` loop:

```js
if (!chromeOk.get(first.file)[block.key]) continue;
```

Measured on a patched copy (9,978 → 10,034):

It is issued as an amendment rather than a new contract because it is one line and the rest of the
